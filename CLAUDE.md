# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

kinetica-physics — движок твёрдых тел на C++17 (только стандартная библиотека), библиотека
`libkinetica-physics.a`, пространство имён `kp`, общий заголовок `<physics.h>`. Обзор для людей —
`README.md`; цель, стандарт кода и обоснование каждого решения — `docs/DEVELOPMENT.md`; как движок
делался, по датам — `docs/JOURNAL.md` (запись добавляется в конце шага, вместе с коммитом).

Родительский `~/GIT/CLAUDE.md` описывает istereolab-sdk: его сборка (`sdk_master.sh`, `bin/ctx`,
`ISTEREOLAB_LIBS_DIR`) сюда не относится, действуют только общие правила стиля.

## Команды

```
cmake -B build && cmake --build build -j                # библиотека, проверки, примеры, приборы (Release)
ctest --test-dir build                                  # unit-tests, no-libm, contact-patch-lemmas (если есть z3), why3-models (если есть why3)
ctest --test-dir build -R no-libm                       # один из трёх тестов ctest
./build/tests/unit-tests                                # все модульные проверки; отказ печатает файл:строку и числа
z3 proofs/<лемма>.smt2                                  # одна лемма: доказана, если ответ unsat
./proofs/check.sh                                       # все леммы и дыры (counterexamples/ обязаны быть sat)
./proofs/why3/check.sh                                  # модели Why3: каждое условие проверки доказано Z3 или Alt-Ergo
cmake -B build -DKP_VIEWER=ON && ./build/viewer/viewer --scene N   # окно; тянет GLFW и ImGui через FetchContent
python3 validation/code_metrics.py [--all|--json]       # стандарт кода: длинные функции, классы, слои, битые ссылки
python3 validation/run.py run|box3d|report              # табло против Box3D → docs/reports/engine-comparison.md
BENCH=14 build/validation/engines/compare-ours realtime 8   # скорость: трёхмерная пирамида 14 × 14 (1 015 кубов);
BENCH=14 build/box3d/compare-box3d 8                    # то же у Box3D — сравнивать мс на кадр
```

Отбора отдельной проверки в `unit-tests` нет: `tests/main.cpp` вызывает пять групп подряд,
проверки — функции в `tests/*Tests.cpp` на макросах `CHECK`/`CHECK_NEAR` из `tests/Check.h`.
`tests/PropertyTests.cpp` — случайные проверки утверждений, намеченных к доказательству (10⁵ входов
на утверждение, свой генератор с постоянным зерном); там же «дыры» — утверждения, про которые
известно, что они неверны (`expectSome`).

Регрессия после правки (порядок из практики):

```
./build/validation/studies/study-state-hash 60 | diff - docs/reports/data/state-hash.txt
KP_REALTIME=1 ./build/validation/studies/study-standard-scenes [rows.jsonl] [бюджет_с] [ключ_сцены]
./build/validation/studies/study-exact-scenes [секунды]
./build/validation/studies/study-overlap-spread [ключ_сцены] [секунды] [вариантов]
./build/validation/studies/study-scale [тел ...]        # цена кадра от числа тел: порознь, столбики, кладка
./build/validation/studies/study-frame-times [ключ_сцены] [секунды]   # рывки: медиана, 99 %, наибольший кадр
./build/validation/studies/study-allocations [ключ_сцены] [секунды]   # обращений к куче на кадр; KP_SITES=1 — откуда
```

`state-hash` — главный критерий: правка, которая не должна менять физику, обязана дать тот же хэш
бит в бит. Строки «точный» совпадают всегда; «быстрый» — если правка не касалась `time_stepping`.
Если физика меняется намеренно, эталон перезаписывается этой же командой, и это видно в diff.
`KP_SLEEP=1` включает сон островов в `study-standard-scenes`.
Время кадра в окне меряется `KP_PACED=1 study-frame-times`: в темпе окна ядра между кадрами сбрасывают
частоту (профиль питания `balanced`), и шаг стоит в 2–3 раза дороже, чем при счёте подряд.
Перекрытие сцены с ударами (куча, чаша) с одного прогона — случайное число: сцена хаотична. Мерить
его `study-overlap-spread` — медианой и наибольшим по 16 вариантам с возмущением скоростей 1 мм/с.

## Архитектура

Слои с зависимостью только вниз; `include/<раздел>` и `src/<раздел>` зеркальны. Порядок снизу
вверх задан списком `LAYERS` в `validation/code_metrics.py`: `math` → `collision/broadphase` →
`collision/shapes` → `collision/narrowphase` → `body` → `joints` → `collision` (поиск пар, луч) →
`dynamics` → `world` → `debug`. Новый `.cpp` нужно вписать в список `src/CMakeLists.txt` — глоба нет.

У `World::step(dt)` два независимых пути, выбор — полем `World::realtime`:

- **Точный** (`dynamics/event_driven/`, `ExactStep`) — эталон, по умолчанию. Шаг режется на
  отрезки в моменты событий: удары (`solveImpacts`) → пары (`PairFinder`) → силы опоры и трения
  одной системой (`ContactSolver::solveRestingContacts`, активный набор + Холецкий) → время
  следующего удара (`timeOfImpact`, консервативное продвижение) → интегрирование до него.
  Цена кадра растёт с числом событий; `World::maxSegments` обрывает шаг для живого окна.
- **Быстрый** (`dynamics/time_stepping/`, `SoftStep`) — подшаги, постоянная цена кадра; настройки в
  `World::soft`. Сочленения тут решаются прямо (`DirectJoints`). Нормали островка — одной жёсткой задачей на весь островок (`IslandNormals`, тот же перебор `ActiveSet`,
  что в точном шаге), и простых тел, и составных: ответ не зависит от отношения масс, стопки стоят без
  провисания. Решается она на рабочем наборе точек (давящие с прошлого раза плюс самые нарушенные),
  остальные только проверяются по скорости — цена растёт с числом давящих точек, а не всех. Каждый
  островок — своя система со своей нумерацией тел, островки решаются заданиями пула потоков. Островки
  крупнее `soft.directContactRows` точек решаются парами на пружинах как в Box3D
  (`SoftContact::solveNormals`, `math/Complementarity.h`, с проксимальной поправкой к прошлому ответу:
  без неё площадка с лишними опорами дрожит) — там шаг приближённый. Пары и точки
  контакта ищутся `soft.contactUpdates` раз за шаг мира (4), подшаги делятся между ними. Сдвиг тел в
  подшаге пробный: пара, вошедшая после него глубже, чем вела её решённая задача (на
  `soft.recheckDepth`), получает ещё один контакт по новой позе, тела возвращаются, и нормали решаются
  снова (`MissedContacts`) — так ловится вершина, которой в площадке на начало обновления не было. Тело,
  получившее удар внутри шага, уходит дальше, чем рассчитывал поиск пар: счёт пути против досягаемости
  списка ведёт `PairReach`, и пары доищутся до сдвига. Отскок считается сразу после удара, внутри
  подшага (в цепочке шаров удары идут по очереди). Трение качения (`soft.rollingResistance`, плечо δ
  в метрах, по умолчанию 0) есть только здесь: в точном шаге качение без потерь. Это сухое трение: на
  остром ребре оно держит тело в неустойчивом равновесии, поэтому движение гасится не им, а
  сопротивлением среды.

Сопротивление среды — `Body::linearDamping` и `angularDamping` (1/с, по умолчанию 0), в обоих шагах:
v ← v / (1 + h c), как в ReactPhysics3D и Box3D. Вязкое затухание исчезает вместе со скоростью и
покоя не создаёт. Окно включает его ползунком (0,1 по умолчанию), кроме сцен с точным ответом.

Геометрия контакта — три ступени, EPA нет: GJK — расстояние разделённых тел; SAT с отсечением
граней — касание многогранников; скруглённые формы (шар, капсула) — ядро плюс радиус. Цилиндр
особый: нет конечного SAT и это не «ядро плюс радиус».

Наблюдение — только снаружи шага: `StepObserver` (таймеры, энергия), `debugGeometry(world)` /
`debugText(world)` — точки, отрезки и текст для любого рендера. Внутри физики строк приборов нет.

Сцены живут в `examples/scenes/` (библиотека `kinetica-scenes`) и общие для окна и приборов —
сцену, добавленную туда, видят и `viewer`, и `study-standard-scenes`, и `study-state-hash`.
`validation/studies/` — замеры, а не тесты «да/нет»: из них выводятся решения.
`validation/engines/` — общие сцены (покой, осыпь, тело в теле, сон, высокий столбик, сочленения) для нашего движка (`compare-ours`, в сборке), Box3D и RP3D
(собираются из `research/refs`, рецепт в шапке файла); `SCENE=ключ compare-ours …` — одна сцена. Каждая сцена идёт в 16 вариантах с малыми
возмущениями; «лучше Box3D» — только по критерию знаков на парах вариантов, не по одному прогону.
Дрожь меряется по всем кадрам после успокоения (скорость точки, развороты, пробуждения), а не по
последнему: глаз видит мигание сна и дёрганье при нулевой средней скорости. Перекрытие тел —
глубиной по разделяющим осям (`overlap_mm`): CCD быстрого шага (упреждающие контакты) спасает от
пролёта, но не от опоры, которую проходы решателя не донесли по длинной цепочке.
Шаг без пересечений по образцу IPC (барьер, метод Ньютона) был сделан и убран 2026-11-18: в бурном
кадре десятки итераций, приёмку в окне не прошёл. Последняя версия — метка git `barrier-step`, разбор —
H16–H27 в журнале попыток; не начинать его заново, не прочитав их.
Попытки улучшить физику — `validation/attempts.jsonl` (гипотеза, прогноз, число, вердикт; только
дописывать). Перед новой гипотезой — посмотреть там, не отклонена ли она уже. Правка быстрого шага
проверяется и табло, и `KP_REALTIME=1 study-standard-scenes`: сцены сравнения не покрывают
составные тела и вёдра.

## Обязательные правила

**Детерминизм** (проверяется тестами и хэшем):
- `-ffp-contract=off` объявлен `PUBLIC` у библиотеки — FMA запрещён и коду, включающему заголовки.
- Никаких `sin`/`cos`/`exp`/`pow`/… из libm в `src/`: тест `no-libm` смотрит неразрешённые символы
  `.a`. Свои функции — `math/` (`sinCos` и др.).
- Порядок обхода не зависит от адресов, хэшей указателей и числа потоков: всё, что идёт в решатель,
  отсортировано по идентификаторам.
- Потоки — только через `math/WorkerPool` (общий пул, по числу ядер): задание пишет в своё место,
  результаты склеиваются в порядке номеров. Так распараллелен поиск пар; `state-hash` обязан совпадать
  при любом `KP_THREADS` (проверять 1, 4, 12).

**Форма кода** (`docs/DEVELOPMENT.md`, раздел 2):
- Функция до 40 строк, класс до 300, публичных методов до дюжины. Один класс — один механизм.
- Переключателей «какой алгоритм» нет: параметр — число с единицей. Флаги `World` (`realtime`,
  `sleeping`, `shockPropagation`) — режимы для сравнения, а не варианты на выбор.
- Нет полей «для совместимости» и мёртвых веток.
- Имена — общепринятые в движках (Box3D, Jolt, PhysX, Rapier); таблица соответствий в
  `docs/DEVELOPMENT.md`. Идентификаторы по-английски, комментарии по-русски: над методом — формула
  в обозначениях кода, источник, единицы; внутри — только неочевидная причина.
- Сильные типы (`BodyId` — `enum class`, не `int`).

**Процесс:**
- Тест или прибор с эталоном раньше кода; где эталон аналитический, допуск записывается до прогона.
- Прежнее ядро `~/GIT/PHYSICS/phys_realflow` — эталон для сравнения, не править его и не копировать
  кусками: алгоритм переносится переписыванием под стандарт.
- Чужой код — только из разрешительных лицензий, с записью в `THIRD_PARTY_NOTICES.md`.
