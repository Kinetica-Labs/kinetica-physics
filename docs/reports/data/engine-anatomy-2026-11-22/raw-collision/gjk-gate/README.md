# Повторный GJK по ширине интервала

На Windows стенд проверил, когда требуется второй вариант проекции GJK. В исходной и отложенной выборках все четыре свойства — оракул постановки, ближайшие точки, наличие контакта и свидетели площадки — дали те же «да/нет», что и два полных спуска. Между численными значениями допустимы различия внутри допусков. [Сводка](summary.json) · [Исходные CSV, код и трассы Windows](native-evidence.tgz)

Один вызов support относится к одной форме. Одна опора разности Минковского вызывает две формы. Счёт для прежнего двухпроходного селектора восстановлен из двух реально исполненных спусков с добавлением двух внешних опор на каждый разрешённый ответ, как требует его исходный код. Стоимость поиска в вершинах различается по формам. Время шага в этом опыте не измерялось. [Счётчики](manifest.json) · [Прежний селектор](../gjk-weights/selector.cpp)

Для разделённых исходных ядер верхняя оценка расстояния равна $U=|v|$, где $v$ — ближайшая точка симплекса. Нижняя оценка равна $L=v·\mathrm{support}(-v)/U$. Допуск $τ=\max(10^{-9}\,\mathrm{м},64ε\max(R_A,R_B,U))$ был зафиксирован до анализа отложенных результатов. В обычном завершении последняя опорная точка уже вычислена для итогового $v$. Если последняя разрешённая итерация сдвинула $v$, программа дополнительно запрашивает одну опору разности. Оценки относятся к вещественной геометрии. В реализации сравниваются округлённые величины. [Предрегистрация](preregistration.md)

**Базовые контракты.** 14 992 из 14 992 прошли в обеих сборках. Селектор повторил 152 запроса, в 32 взял альтернативу. Девять отдельных проверок дали побайтно одинаковый выход, включая конечную дальность, неограниченный запрос, совпадающие центры, перекрытие ядер и расстояние $10^{200}$ м. При перекрытии ядер или достоверном превышении дальности сохраняется штатный результат. Уменьшенный цилиндр рассматривается отдельно от исходной геометрии. Сборка использовала clang для x86-64 Windows GNU с расширенной точностью long double в альтернативной проекции. Для других ABI и времени шага нужны отдельные проверки.

Для повторного разбора распакуйте архив в подкаталог results рядом с анализатором. Запустите анализатор из корня репозитория. [Сценарий разбора](analyze.py)
