# Какие величины Box3D, Jolt и Bullet считают одновременно

| Движок | Что занимает соседние полосы SIMD | Как устроена память |
|---|---|---|
| Box3D | Контакты независимых пар одного цвета графа. У каждой полосы свои тела и свой накопленный импульс. | Для всего набора пакетов выпуклых контактов решатель заранее вычисляет число байтов и запрашивает один блок в арене мира. |
| Jolt | При запросе лучом к дереву столкновений четыре полосы проверяют четыре дочерних ограничивающих бокса. | В узле рядом лежат четыре значения минимального X, отдельно четыре минимального Y и так далее по шести границам. |
| Bullet | Решатель обрабатывает одну строку связи. SIMD применяется к компонентам линейной и угловой скорости и нормали в этой строке. | Отдельные плотные массивы содержат тела решателя, строки контакта, трения и прочих связей. При завершении решения их длины сбрасываются с сохранением ёмкости. |

### Box3D — подготовленные пакеты контактов

Перед циклом внутренних подшагов Box3D готовит контакты и сочленения. Ширина пакета выпуклых контактов на x86 может составлять восемь `float` при наличии собранного ядра AVX2, поддержки процессора и сохранения регистров операционной системой. Для четырёх полос есть реализации SSE2 и NEON, а сборка с отключённым SIMD использует скалярные операции. При переполнении стека временных данных доступен запасной путь с выделением памяти. [Подготовка до подшагов](https://github.com/erincatto/box3d/blob/be8c7318901dbb14b9fbb26fe0a7a48850f53b0e/src/solver.c#L1227-L1252) · [Размер блока](https://github.com/erincatto/box3d/blob/be8c7318901dbb14b9fbb26fe0a7a48850f53b0e/src/solver.c#L1566-L1575) · [Арена и переполнение](https://github.com/erincatto/box3d/blob/be8c7318901dbb14b9fbb26fe0a7a48850f53b0e/src/arena_allocator.c#L25-L60) · [Проверка AVX2](https://github.com/erincatto/box3d/blob/be8c7318901dbb14b9fbb26fe0a7a48850f53b0e/src/simd.c#L52-L96) · [Выбор реализации](https://github.com/erincatto/box3d/blob/be8c7318901dbb14b9fbb26fe0a7a48850f53b0e/src/simd.h#L12-L30) · [Вызов ядра](https://github.com/erincatto/box3d/blob/be8c7318901dbb14b9fbb26fe0a7a48850f53b0e/src/contact_solver.c#L1074-L1086)

В нашем захвате обе пары касаются одного динамического куба. Раскраска помещает их в разные группы, поэтому эти две пары не заполняют один пакет. Наш прибор также делает восемь публичных вызовов с одним внутренним подшагом каждый. Для объяснения разрыва по времени стоит измерить стоимость подготовки внутри каждого вызова. [Правило независимости пар](https://github.com/erincatto/box3d/blob/be8c7318901dbb14b9fbb26fe0a7a48850f53b0e/src/constraint_graph.c#L93-L110) · [Адаптер нашего захвата](../../../../validation/engines/grip_box3d.cpp)

### Jolt — четыре ограничивающих бокса в одном узле

В широкофазном поиске луч проходит дерево и получает интервалы пересечения сразу для четырёх боксов. Чтобы собрать шесть векторов границ, обход загружает шесть последовательных групп по четыре числа. Например, операция поэлементного минимума имеет ветви SSE, NEON, RVV и покомпонентную реализацию. Выбор для этой операции определяют макросы сборки. Перенос такого узла в Kinetica имеет смысл оценивать на сериях лучей или кандидатов столкновений с известным числом посещённых узлов. [Представление узла](https://github.com/jrouwe/JoltPhysics/blob/864a3d061dc53aa57473aca317742a4a0af4e99d/Jolt/Physics/Collision/BroadPhase/QuadTree.h#L115-L129) · [Загрузка границ](https://github.com/jrouwe/JoltPhysics/blob/864a3d061dc53aa57473aca317742a4a0af4e99d/Jolt/Physics/Collision/BroadPhase/QuadTree.cpp#L1038-L1046) · [Пересечение с лучом](https://github.com/jrouwe/JoltPhysics/blob/864a3d061dc53aa57473aca317742a4a0af4e99d/Jolt/Geometry/RayAABox.h#L72-L130) · [Варианты минимума](https://github.com/jrouwe/JoltPhysics/blob/864a3d061dc53aa57473aca317742a4a0af4e99d/Jolt/Math/Vec4.inl#L188-L207)

### Bullet — исполнимый скалярный эталон

У одной строки ограничения есть скалярная реализация, которая вычисляет изменение импульса и ограничивает его заданным интервалом. При включённом `SOLVER_SIMD` и наличии соответствующего кода решатель может выбрать SSE2. В сборке с `BT_ALLOW_SSE4` он дополнительно проверяет SSE4.1 и FMA3 для двух видов строк. У контейнера временных тел выравнивание 16 байт. Для учебного движка удобно перенять контракт ядра и прогонять одну строку через обе реализации. При использовании FMA нужно отдельно проверить округление около границы сцепления. [Скалярная строка](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/src/BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.cpp#L45-L77) · [Выбор ядра](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/src/BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.cpp#L360-L382) · [Массивы решателя](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/src/BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.h#L54-L61) · [Выравнивание](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/src/LinearMath/btAlignedObjectArray.h#L45-L54) · [Возврат ёмкости в повторное использование](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/src/BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.cpp#L1848-L1853)

**⚠️ Стресс-тест.** Для Box3D различать одну пару, два контакта с общим телом и много независимых пар. Для обхода Jolt проверять луч, параллельный грани бокса, и частично заполненный узел. Для строки Bullet проверять импульс на нижней и верхней границе. Из исходников установлены единица пакетной обработки и условия выбора кода. Фактическая ветвь и выигрыш на конкретном бинарном файле требуют измерения.
